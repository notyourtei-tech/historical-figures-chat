# 系统架构与数据边界

## 目标

万古灵犀的架构目标是让核心对话在没有第三方账号、模型密钥或数据库时仍可用；当运营方选择接入云服务时，用户数据、权限和供应商失败应有清晰的退化路径。

## 请求路径

```text
用户输入
  → Chat 页面（浏览器状态与可访问性反馈）
  → /api/chat（来源校验、限流、内容治理、输入清洗）
  → 人物行为契约 + 有界上下文
  → 默认本地人物引擎
       └─ 可选 online 模式：已同意后调用已配置模型服务
  → SSE 片段回传
  → 浏览器按节奏呈现、分组并保存本机对话
```

人物的连续回复通过受控分段符解析为多条消息；这不是客户端随机拆分。角色“插话”只基于当前草稿在浏览器本地生成建议，草稿不会因这一功能额外发送给模型服务。

## 存储与认证

| 数据 | 默认位置 | 何时离开浏览器 | 约束 |
| --- | --- | --- | --- |
| 页面语言、偏好、未登录会话 | `localStorage` | 不会自动云同步 | 受浏览器存储配额限制 |
| 本机体验登录邮箱 | `localStorage` | 不上传 | 密码既不保存也不传输；它不是云端账户 |
| 云端会话 | Supabase（可选） | 用户通过 Supabase 认证后 | RLS 限制为当前用户自己的记录 |
| 分析事件 | 首方 API（需同意） | 仅启用分析后 | 禁止聊天正文、邮箱、IP、URL 参数、自由文本 |
| 错误事件 | Sentry（可选） | 配置 DSN 后 | 初始化时关闭默认 PII，并剥离请求体、Cookie、Header 与用户信息 |

`SUPABASE_SERVICE_ROLE_KEY` 仅允许在服务端使用。它绝不能进入客户端包、`NEXT_PUBLIC_` 变量、浏览器日志或 Git。

## API 面

| 路由 | 用途 | 身份要求 | 缓存 |
| --- | --- | --- | --- |
| `POST /api/greeting` | 获取人物开场白 | 无 | 禁止缓存 |
| `POST /api/chat?stream=1` | 流式对话 | 无，但需要隐私同意 | 禁止缓存 |
| `GET/PUT/DELETE /api/conversations/:celebrityId` | 云端会话 | Supabase 会话 | 动态 / 禁止缓存 |
| `GET /api/conversations` | 云端会话索引 | Supabase 会话 | 动态 / 禁止缓存 |
| `PUT /api/privacy/consent` | 记录已同意的选择 | 无 | 禁止缓存 |
| `POST /api/analytics` | 最小化产品事件 | 分析同意 | 禁止缓存 |
| `GET /api/health` | 可用性探针 | 无 | 禁止缓存 |

未认证访问会话 API 时，服务返回可预期的本机模式结果；客户端不将此视作服务器错误，也不创建隐形访客账户。

## 安全与韧性

1. 所有公共聊天入口执行来源检查、输入长度限制、人物 ID 白名单和限流。
2. 内容治理在生成前运行；拦截时返回用户可理解的说明，不在日志中复制原始对话。
3. 在线模型模式是显式开关。供应商超时、限流或返回异常时，系统回退到本地人物引擎。
4. 浏览器的本地会话保存有大小上限，达到上限时保留较新的半段内容，避免整个写入失败。
5. 响应安全头、CSP、禁止 API 缓存和受限的远程图片域名在 `next.config.ts` 中统一配置。
6. 健康检查只暴露集成配置的高层状态，不暴露密钥、模型响应或用户数据。

## 可观测性

产品事件以 `src/lib/analytics-events.ts` 为唯一事件字典。每个事件都应回答一个产品问题，并通过 [指标计划](measurement-plan.md) 的字段审查。运行故障通过结构化上下文上报；生产运营流程见 [operations.md](operations.md)。

## 不在此架构中承诺的事

- 不把第三方免费套餐、模型可用性或免费短信描述为永久保证。
- 不将 Supabase、Sentry、Upstash 或模型供应商的默认设置视为生产配置。
- 不以端到端测试代替真实 Android/iOS、OAuth 回调和可访问性辅助技术的发布前验收。
